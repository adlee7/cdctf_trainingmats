What is Network Traffic Analysis?

Network Traffic Analysis (NTA) is the practice of examining data captured as it moves across a network — typically recorded in a packet capture (pcap) file — to understand what happened, spot suspicious behavior, or recover hidden data. Every packet carries metadata (source/destination IP, port, protocol) and often a payload, and both can hold clues.

In a CTF, NTA challenges usually hand you a pcap file and ask you to find something inside it: a file transferred over the wire, credentials sent in the clear, a command-and-control connection, or data hidden in a protocol field.

Common NTA Challenge Types

  • Protocol Identification: Figuring out what protocols are in use and what "normal" traffic looks like for this capture.
  • Conversation Following: Reconstructing an entire exchange between two hosts (e.g. an HTTP request/response or a TCP stream) to read what was actually sent.
  • File Carving from Traffic: Extracting a file (image, document, archive) that was transferred across the network.
  • Suspicious Traffic Detection: Spotting connections to unusual ports, beaconing behavior, or traffic that doesn't match its stated protocol.
  • Payload Decoding: Recognizing and decoding data that's been encoded (hex, Base64, etc.) within a packet's payload.

What is Log Analysis?

Log analysis is the practice of reading through system- or application-generated log files to reconstruct events, spot anomalies, or find specific pieces of information. Where NTA looks at what crossed the network, log analysis looks at what a system recorded about its own activity — logins, processes, commands, errors, and more.

In a CTF, log analysis challenges usually hand you a (often large) text log file and ask you to filter, search, and summarize it to answer a question — which is exactly the kind of task the Linux command line excels at.

Common Log Analysis Challenge Types

  • Brute Force Detection: Counting repeated failed attempts to spot an attacker and the account or service they targeted.
  • Timeline Reconstruction: Ordering events by timestamp to understand the sequence of an incident.
  • Indicator Extraction: Pulling out IP addresses, usernames, or hostnames associated with suspicious activity.
  • Encoded Data Recovery: Spotting and decoding Base64 or other encoded strings that have been logged, intentionally or not.

Toolbox

This MAT doesn't include an actual packet capture file to open, so we won't be using Wireshark directly here — but it's the single most important tool for real NTA challenges, and you should get comfortable with it if you want to do more CTFs. The resources below will get you started.

Wireshark (Essential — Not Used in This MAT)

  • Wireshark: The standard graphical tool for opening and analyzing pcap files, with powerful filtering, stream-following, and file-export features.
  • Wireshark User's Guide — Introduction: The official getting-started chapter; walks through installing Wireshark and capturing or opening your first file.
  • Working With Captured Packets: Official guide section covering filtering, following streams, and exporting objects — the core skills for CTF-style NTA.
  • Display Filter Reference: The official reference for Wireshark's filter syntax (e.g. http, dns, tcp.port == 4444).

Command-Line Network Tools

  • tcpdump: A command-line packet capture and filtering tool, useful when a GUI isn't available.
  • tshark: Wireshark's command-line counterpart, useful for scripting or quick filtering without the GUI.
  • NetworkMiner: A network forensics tool that automatically extracts files, credentials, and sessions from a pcap.

Log Analysis Tools

  • grep: Searches text for lines matching a pattern — the workhorse of CLI log analysis.
  • awk: A pattern-scanning and text-processing language, great for pulling out specific columns/fields from structured log lines.
  • sed: A stream editor for searching and transforming text, often used alongside grep and awk.
  • sort & uniq: Commonly chained together (sort | uniq -c) to count how often each distinct line or value appears.
  • journalctl: Queries the systemd journal on modern Linux systems, useful if you're handed a live system rather than a flat log file.
  • jq: A command-line JSON processor, useful when logs are structured as JSON rather than plain text.
  • base64: Encodes and decodes Base64 data directly from the command line (base64 -d to decode).

Before You Continue

Nice work pulling data out of individual packets. Log analysis works a little differently: instead of reading structured fields packet-by-packet, you're usually scanning large volumes of plain text for patterns — which is where command-line tools like grep and awk really shine.
